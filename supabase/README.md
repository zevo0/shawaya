# ربط شواية بـ Supabase — دليل الإعداد

هذا الدليل يشرح كيف تُفعّل الربط الحي بين **لوحة التحكم** (`/admin`) و**الموقع** بحيث
أي تعديل في اللوحة يظهر فوراً على الموقع دون أي كود إضافي أو إعادة نشر.

## 1) أنشئ مشروع Supabase
1. افتح https://supabase.com وأنشئ مشروعاً جديداً.
2. من **Project Settings → API** انسخ:
   - **Project URL**
   - **anon public key** (لا تستخدم أبداً `service_role` في الواجهة الأمامية)

## 2) شغّل السكيمة
1. افتح **SQL Editor** داخل مشروع Supabase.
2. الصق محتوى الملف `supabase/schema.sql` بالكامل ونفّذه (Run).
   - ينشئ كل الجداول: `settings, categories, products, option_groups,
     product_options, offers, orders, order_items, media`.
   - يفعّل Row Level Security بحيث:
     - أي زائر للموقع (anon) يقرأ المنتجات/التصنيفات/العروض/الإعدادات المنشورة فقط،
       ويستطيع إنشاء طلب فقط (لا يقرأ ولا يعدّل طلبات الآخرين).
     - فقط المستخدم المسجّل دخوله (أنت، عبر لوحة التحكم) يملك صلاحية الإضافة/التعديل/الحذف.
   - ينشئ Storage bucket باسم `media` لمكتبة الوسائط، مع صلاحية قراءة عامة وكتابة للمدير فقط.
   - يفعّل Realtime على الجداول الأساسية حتى ينعكس أي تغيير على الموقع فوراً.
   - يزرع بيانات تجريبية (تصنيفات ومنتجات) مطابقة لما كان يظهر بدون Supabase.

## 3) أنشئ حساب المدير
1. من **Authentication → Users** داخل Supabase، اضغط **Add user**.
2. أدخل بريدك الإلكتروني وكلمة مرور قوية. هذا هو حساب دخولك للوحة التحكم.
   (لا يوجد تسجيل حسابات عامة — فقط الحسابات التي تنشئها أنت يدوياً من Supabase.)

## 4) اربط الموقع بالمفاتيح
افتح `config.js` في جذر المشروع وعدّل:

```js
supabase: {
  url: "https://xxxxxxxx.supabase.co",
  anonKey: "eyJhbGciOi...",
},
```

هذا الملف الواحد يُستخدم من قِبل **كل من الموقع ولوحة التحكم** (اللوحة تقرأ
`../config.js`)، لذلك تحتاج لتعديله في مكان واحد فقط.

## 5) افتح لوحة التحكم
- اذهب إلى `/admin/index.html` وسجّل الدخول بالحساب الذي أنشأته في الخطوة 3.
- من الرئيسية يمكنك فتح/إغلاق المطعم فوراً — هذا الزر يمنع إتمام أي طلب واتساب
  جديد على الموقع طالما المطعم "مغلق"، ويظهر شريط تنبيه في سلة الزبون.

## كيف يبقى كل شيء متزامناً بدون كود؟
- **مصدر الحقيقة الوحيد** لكل بيانات المنيو والإعدادات هو Supabase — لا يوجد أي
  محتوى مكتوب داخل كود الموقع (`js/menu.js` يحوي فقط بيانات تجريبية احتياطية
  تُستخدم فقط إن لم يكن Supabase مربوطاً بعد).
- الموقع (`js/supabase.js`) يشترك عبر Supabase Realtime في تغييرات
  `settings/products/categories/offers/option_groups/product_options`، فيعيد
  تحميل المنيو والإعدادات تلقائياً خلال ثوانٍ من أي حفظ في اللوحة — بدون تحديث الصفحة يدوياً حتى.
- كل الصور تُرفع مرة واحدة في **مكتبة الوسائط** ثم تُختار من أي نموذج (منتج/تصنيف/عرض/إعدادات/SEO) — لا تكرار لرفع نفس الصورة.
- الطلبات التي يرسلها الزبائن عبر واتساب تُسجَّل أولاً في جدول `orders` قبل فتح
  واتساب، فتظهر فوراً في **إدارة الطلبات** وفي إحصائيات **الرئيسية**.

## ملاحظات أمنية
- مفتاح `anonKey` عام بطبيعته ومخصص للاستخدام في المتصفح — الحماية الفعلية تأتي
  من سياسات RLS في `schema.sql` (القراءة عامة، الكتابة تتطلب تسجيل دخول).
- لا تضع أبداً `service_role key` في `config.js` أو أي ملف يصل إليه المتصفح.
- لإضافة مدير آخر، أنشئ له مستخدماً من **Authentication → Users** في Supabase؛
  لا حاجة لتعديل أي كود.

## تحديث: حذف تيك توك وسناب شات
تم حذف حقلي `tiktok_url` و`snapchat_url` من `schema.sql` ومن لوحة التحكم والموقع.
إن كان مشروع Supabase الخاص بك يعمل مسبقاً (تم تشغيل السكيمة القديمة)، نفّذ هذا
الأمر مرة واحدة داخل **SQL Editor** لحذف العمودين من قاعدة البيانات الفعلية:

```sql
alter table public.settings drop column if exists tiktok_url;
alter table public.settings drop column if exists snapchat_url;
```
